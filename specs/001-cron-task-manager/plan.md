# Implementation Plan: Cron Task Manager

**Branch**: `001-cron-task-manager` | **Date**: 2026-05-12 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/001-cron-task-manager/spec.md`

## Summary

A two-service monorepo system: a standalone Node.js scheduler backend that executes cron-based
tasks as subprocesses and exposes a tRPC API; and a Next.js admin UI that communicates with the
scheduler exclusively via tRPC (through Next.js server actions). Shared types, Zod schemas,
repository interfaces, and the tRPC router definition all live in `@repo/common`.

## Technical Context

**Language/Version**: TypeScript 5.x strict; Node.js ≥ 22.6 (scheduler), Node.js ≥ 18 (web)

**Requirement added post-spec**: FR-012 — Tasks support per-task environment variables
(`env: Record<string, string>`) injected into the subprocess at execution time, merged over
the system environment. The task form includes a key/value editor for env vars.

**Primary Dependencies**:

| Package | App | Purpose |
|---------|-----|---------|
| `@trpc/server` | common, scheduler | Router definition + standalone HTTP adapter |
| `@trpc/client` | web | Typed HTTP client |
| `zod` | common | Schema validation |
| `node-cron` | scheduler | Cron scheduling |
| `json5` | scheduler | JSON5 file read/write |
| `jose` | scheduler | JWT sign/verify |
| `@monaco-editor/react` | web | Code editor (shell/python/JS scripts) |
| `cronstrue` | web | Cron expression → plain English |
| `next-themes` | web | Dark/light mode |
| `lucide-react` | web | Icons (no emoji) |

**Storage**: JSON5 flat files in `$DATA_DIR/` — abstracted behind `ITaskRepository` /
`IExecutionRepository` interfaces for future swap to a database.

**Testing**: Not required for v1 (not specified in feature spec).

**Target Platform**: Node.js server + modern web browser (Chrome/Firefox/Safari).

**Project Type**: Full-stack monorepo web application.

**Performance Goals**:
- Cron expression UI feedback: < 500ms after user stops typing (SC-002)
- Manual trigger response: < 3s (SC-003)
- History page load: < 2s (SC-004)

**Constraints**:
- Single admin user; no RBAC.
- No build step for scheduler (native Node.js TypeScript, `"type": "module"`).
- Concurrent run policy: skip + log skipped (spec decision).
- Output truncation: 100,000 chars per stdout/stderr.

**Scale/Scope**: Single-user admin tool; 10s–100s of tasks; indefinite execution history.

## Complexity Tracking

| Apparent violation | Why needed | Simpler alternative rejected because |
|-------------------|------------|--------------------------------------|
| Repository interface in common | User explicitly requires storage abstraction for future DB swap | Direct JSON5 access in procedures would make storage migration require changes in common (shared package) and scheduler simultaneously; the interface isolates the change |
| tRPC router in common (not in scheduler) | `AppRouter` type must be accessible to web without cross-app source import | If router lived in `apps/scheduler`, `apps/web` would need to import from another app — prohibited by Constitution Principle IV |
